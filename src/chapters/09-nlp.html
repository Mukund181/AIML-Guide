Text Preprocessing & Subword Tokenization

Computers cannot process raw strings directly. Text must be normalized, segmented, and mapped to discrete numerical identifiers before being transformed into dense vector representations.

1. Traditional Text Preprocessing Pipeline

✂️

Stemming (Crude Truncation)

Heuristic rule-based chopping of word suffixes (e.g. Porter Stemmer). Fast but creates non-words: "studies" \(\to\) "studi", "meeting" \(\to\) "meet".

📖

Lemmatization (Vocabulary Root)

Uses morphological analysis and a dictionary (WordNet) to return the actual dictionary root (lemma): "better" \(\to\) "good", "was" \(\to\) "be".

🚫

Stopword Removal

Filtering out high-frequency functional words ("the", "is", "at") that carry little domain topicality in classical bag-of-words pipelines.

⚠️

When NOT to Clean

In modern LLMs and Transformers, do not strip punctuation, casing, or stopwords! Grammatical markers and capitalization contain vital syntactic clues.

2. The Subword Tokenization Revolution

Early NLP faced a dilemma: Word-level tokenization resulted in massive vocabularies (millions of words) and failed on out-of-vocabulary (OOV) typos; Character-level tokenization eliminated OOV words but created excessively long sequences with diluted semantic meaning. Modern LLMs solve this via Subword Tokenization algorithms.

Algorithm How It Works Vocabulary Construction Models Using It
Byte-Pair Encoding (BPE) Starts with individual characters. Iteratively counts the most frequent adjacent character pairs and merges them into new subword units. Bottom-up greedy frequency merging until desired vocabulary size is reached. GPT-2, GPT-3, GPT-4, RoBERTa, LLaMA
WordPiece Similar to BPE, but selects pair merges that maximize the likelihood of the training corpus under a unigram language model rather than pure frequency. Likelihood maximization scoring: \(\frac{\text{count}(ab)}{\text{count}(a)\times\text{count}(b)}\). BERT, DistilBERT, Electra
SentencePiece / Unigram Treats raw input as a stream of bytes (including whitespace as a special character _). Language-independent; no language-specific pre-tokenizers needed. Starts with a huge vocabulary and iteratively prunes low-probability subwords (top-down). T5, ALBERT, LLaMA 2/3, Mistral
tokenization_comparison.py 
from transformers import AutoTokenizer

# 1. Load tokenizers from two modern model families
bert_tok  = AutoTokenizer.from_pretrained("bert-base-uncased")     # WordPiece
gpt2_tok  = AutoTokenizer.from_pretrained("gpt2")                  # Byte-level BPE

sample_text = "Antigravity is extraordinarily exhilarating!"

# Tokenize with BERT (WordPiece prefixes continuations with '##')
bert_tokens = bert_tok.tokenize(sample_text)
bert_ids    = bert_tok.encode(sample_text)
print("BERT WordPiece tokens:", bert_tokens)
# ['anti', '##gra', '##vity', 'is', 'extraordinarily', 'ex', '##hilar', '##ating', '!']

# Tokenize with GPT-2 (Byte-level BPE prefixes spaces with special character)
gpt_tokens = gpt2_tok.tokenize(sample_text)
print("GPT-2 BPE tokens:     ", gpt_tokens)
# ['Ant', 'ig', 'ravity', 'Ġis', 'Ġextraordinarily', 'Ġex', 'hil', 'ar', 'ating', '!']

Bag of Words, N-grams & TF-IDF

Before deep neural networks, statistical frequency models served as the standard numerical representation for document search and classification.

1. The Mathematics of TF-IDF

TF-IDF (Term Frequency – Inverse Document Frequency) balances how frequently a word appears inside a document against how common that word is across the entire corpus. A word that appears frequently in document A but rarely in any other document receives a high score.

\text{TF}(t, d) = \frac{\text{count}(t \in d)}{\sum_{t' \in d} \text{count}(t')}, \qquad \text{IDF}(t, D) = \log\left(\frac{1 + |D|}{1 + |\{d \in D : t \in d\}|}\right) + 1
\text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \text{IDF}(t, D)
tfidf_and_cosine.py 
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
import pandas as pd

corpus = [
    "Deep learning models require GPUs for accelerated matrix multiplication.",
    "PyTorch provides dynamic computation graphs and automatic differentiation.",
    "Linear algebra and matrix multiplication are fundamental for machine learning."
]

# Vectorize using unigrams and bigrams (ngram_range=(1,2))
vectorizer = TfidfVectorizer(ngram_range=(1, 2), stop_words='english')
tfidf_matrix = vectorizer.fit_transform(corpus)

# Compute pairwise cosine similarity between all documents
sim_matrix = cosine_similarity(tfidf_matrix, tfidf_matrix)

df_sim = pd.DataFrame(sim_matrix, columns=["Doc 1", "Doc 2", "Doc 3"], 
                              index=["Doc 1", "Doc 2", "Doc 3"])
print("TF-IDF Cosine Similarity Matrix:\n", df_sim.round(3))
The Limitations of TF-IDF:
  1. No Semantic Understanding: "automobile" and "car" share zero vocabulary overlap; their TF-IDF vector dot product is exactly 0.0.
  2. Extreme Sparsity: Vector length equals total vocabulary size (\(V \approx 50,000+\)), where 99.9% of entries are zeros.
  3. Disregards Word Order: "Not bad, actually good" and "Not good, actually bad" have identical Bag-of-Words vectors!

Word Embeddings & Semantic Similarity

The foundational breakthrough of modern NLP was mapping words to dense continuous vector spaces (\(\mathbb{R}^{300}\)) where geometric distance corresponds directly to semantic similarity: "You shall know a word by the company it keeps" (J.R. Firth, 1957).

1. Word2Vec Architectures: CBOW vs Skip-Gram

🎯

Continuous Bag of Words (CBOW)

Predicts a central target word \(w_t\) given a window of surrounding context words: \(P(w_t \mid w_{t-2}, w_{t-1}, w_{t+1}, w_{t+2})\). Faster to train, higher accuracy on frequent words.

⚡

Skip-Gram Architecture

Inverts the task: takes a single target word \(w_t\) and predicts the distribution of context words: \(P(w_{t+j} \mid w_t)\). Performs exceptionally well on rare words and smaller datasets.

📉

Negative Sampling (SGNS)

Standard softmax requires calculating denominator sums over all \(V=100,000\) vocabulary words. Negative sampling turns multi-class classification into binary logistic regression using 5–20 random noise words.

👑

Vector Arithmetic & Analogies

Linear vector offsets capture relational semantics: \(\mathbf{v}_{\text{King}} - \mathbf{v}_{\text{Man}} + \mathbf{v}_{\text{Woman}} \approx \mathbf{v}_{\text{Queen}}\), or \(\mathbf{v}_{\text{Paris}} - \mathbf{v}_{\text{France}} + \mathbf{v}_{\text{Germany}} \approx \mathbf{v}_{\text{Berlin}}\).

2. Sentence Embeddings with Sentence-Transformers

While Word2Vec represents individual words, modern semantic search requires encoding whole sentences or paragraphs into fixed-length dense representations using fine-tuned bi-encoders (Reimers & Gurevych, 2019).

semantic_similarity.py 
# pip install sentence-transformers
from sentence_transformers import SentenceTransformer, util

# 1. Load an industry-standard lightweight embedding model
model = SentenceTransformer('all-MiniLM-L6-v2')

queries = ["How do I optimize neural network training speed?"]
candidate_docs = [
    "Using mixed precision fp16 and larger batch sizes accelerates GPU throughput.",
    "The French revolution took place in the late eighteenth century.",
    "PyTorch DataLoader num_workers allows asynchronous parallel batch loading.",
    "Baking sourdough bread requires flour, water, salt, and wild yeast."
]

# 2. Encode sentences into dense 384-dimensional vectors
query_vec = model.encode(queries, convert_to_tensor=True)
doc_vecs  = model.encode(candidate_docs, convert_to_tensor=True)

# 3. Calculate cosine similarity scores
cosine_scores = util.cos_sim(query_vec, doc_vecs)[0]

# 4. Display ranked results
ranked_indices = cosine_scores.argsort(descending=True)
print("Query:", queries[0])
for rank, idx in enumerate(ranked_indices):
    score = cosine_scores[idx].item()
    print(f"  Rank {rank+1} (Score: {score:.4f}): {candidate_docs[idx]}")

Attention, Self-Attention & Positional Encodings

Before Transformers, Recurrent Neural Networks (LSTMs/GRUs) processed tokens sequentially from left to right, creating two fatal bottlenecks: (1) information loss over long distances, and (2) inability to train in parallel on GPUs. The Self-Attention mechanism solves both.

1. Attention Taxonomy in NLP

🔄

Bidirectional Self-Attention

Every token can attend to every other token in the sequence (both left and right). Used in Encoder-only models (BERT) for understanding and classification.

🛡️

Causal / Masked Attention

Tokens can ONLY attend to previous tokens (\(j \le i\)). An upper-triangular mask of \(-\infty\) is applied before softmax. Used in Decoder-only models (GPT) for autoregressive generation.

🔀

Cross-Attention

Queries come from the decoder, while Keys and Values come from the encoder. Used in Encoder-Decoder models (T5, Whisper) for translation and transcription.

🧩

Multi-Query & Grouped-Query

GQA (Grouped-Query Attention) shares Key-Value heads across Query heads, reducing KV cache VRAM by 8x during LLM generation (used in LLaMA-2/3 & Mistral).

2. Positional Encodings: Sinusoidal vs Rotary (RoPE)

Because self-attention operations are permutation invariant (computing identical results regardless of word order), token positions must be explicitly added to the embeddings:

  • Sinusoidal Absolute Positional Encoding (Vaswani 2017): Adds static geometric sine/cosine waves of varying frequencies. Does not generalize well to context lengths beyond training window.
  • Rotary Position Embeddings (RoPE - Su et al., 2021): Encodes relative position by rotating Query and Key vectors in the 2D complex plane:
    \(\mathbf{q}_m = \mathbf{R}_{\Theta, m}^d \mathbf{W}_q \mathbf{x}_m, \quad \mathbf{k}_n = \mathbf{R}_{\Theta, n}^d \mathbf{W}_k \mathbf{x}_n \quad \implies \quad \langle \mathbf{q}_m, \mathbf{k}_n \rangle = g(\mathbf{x}_m, \mathbf{x}_n, m - n)\)
    The inner product depends solely on the relative distance \(m - n\). RoPE is the undisputed standard in modern LLMs (LLaMA 3, Mistral, Gemma, Qwen) because it allows seamless context length extrapolation via RoPE scaling!

Fine-Tuning BERT for Text Classification

In industry, encoder-only models like BERT remain the most cost-effective solution for classification tasks — running in sub-10ms with 100x lower inference cost than calling an LLM API.

fine_tune_bert.py 
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification
from transformers import Trainer, TrainingArguments
from datasets import load_dataset

# 1. Load Pretrained BERT Model & Tokenizer with classification head
model_name = "bert-base-uncased"
tokenizer  = AutoTokenizer.from_pretrained(model_name)
model      = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2)

# 2. Tokenize dataset
def tokenize_function(examples):
    return tokenizer(examples["text"], padding="max_length", truncation=True, max_length=128)

dataset = load_dataset("imdb", split={"train": "train[:2000]", "test": "test[:500]"})
tokenized_datasets = dataset.map(tokenize_function, batched=True)

# 3. Configure Fine-tuning parameters
training_args = TrainingArguments(
    output_dir="./bert_sentiment_output",
    eval_strategy="epoch",
    learning_rate=2e-5,          # Low learning rate for pretrained weights
    per_device_train_batch_size=16,
    num_train_epochs=3,
    weight_decay=0.01,
    fp16=torch.cuda.is_available()
)

# 4. Train with Hugging Face Trainer
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["test"],
)
# trainer.train()
print("✅ BERT Classification pipeline configured!")
